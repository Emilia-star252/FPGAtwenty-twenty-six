## 3. 量化可行性（numpy 仿真）

官方两个现成模型（yolo_face_uint8_15 / fire_detect_sim_quant_uint8）都是 QDQ 结构：
输入是 uint8 值域的 float 张量 + QuantizeLinear，权重 uint8。硬 NPU 大概率只吃量化图，
所以先算清楚量化代价：

- float test acc = 99.72%
- int8 权重 / uint8 激活 仿真 acc = 100.00%（1/360 个样本预测翻转）
- 参数量 724：float32 2896 B → int8 权重 672 B
- 每张量 scale：input 0.003922，w1 5.381e-02，w2 2.083e-02，w3 1.893e-02

结论：量化损失在这个任务上可以忽略（类别没变），可以走 QDQ 导出；
但 QDQ 图能否被 Alnpu 后端接受，只有在板上试才知道（见 5. 风险）。

## 4. 鲁棒性（传感器误差敏感度）

不动模型，只改喂进去的三个量（等价于板上增益误差/零点漂移/量化变粗/噪声）：

| 场景 | 准确率 | 相对基线 | 与基线预测一致 |
| --- | ---: | ---: | ---: |
| 基线（无误差） | 99.72% | +0.00pp | 100.00% |
| 电压增益 +2% | 99.72% | +0.00pp | 100.00% |
| 电压增益 -2% | 99.72% | +0.00pp | 100.00% |
| 电流增益 +2% | 100.00% | +0.28pp | 99.72% |
| 电流增益 -2% | 99.72% | +0.00pp | 100.00% |
| 电流增益 +5% | 97.78% | -1.94pp | 97.50% |
| 电流零点 +20mA | 100.00% | +0.28pp | 99.72% |
| 占空比增益 +2% | 99.72% | +0.00pp | 100.00% |
| 全通道 +5% | 97.78% | -1.94pp | 97.50% |
| 量化变粗（V 0.1V / I 10mA / D 1%） | 99.72% | +0.00pp | 100.00% |
| 测量噪声 σ=2% | 99.44% | -0.28pp | 99.72% |
| 测量噪声 σ=5% | 96.11% | -3.61pp | 95.83% |

读法：±2% 增益误差和 10mV/1% 的粗量化基本不掉点；±5% 增益或 5% 噪声掉 2~4 个点，掉的主要是贴着类别边界（I≈0.7A / 1.8A）的样本。
这说明**标定/bias 比模型容量更重要**：真实板上先保证电流采样准，再谈网络加深。

## 5. 导出产物

- `out\dcdc_npu.onnx`（3564 B）：opset 13，Gemm→Relu→Gemm→Relu→Gemm→Softmax（float32，给 CpuRef/CpuAcc 兜底用）
- `dcdc_npu_qdq.onnx`：QDQ + 1×1 Conv（输入 [1,3,1,1]，Conv 权重 uint8、bias int32、激活 uint8）—— **先试这个上 Alnpu**
  - 与独立量化实现数值对拍偏差 0.0e+00；与 float 模型类别一致率 99.72%；测试集准确率 100.00%
  - 量化参数：输入 scale 0.003922，conv1 w_scale 4.9932e-02 / a_scale 2.0406e-02，conv2 w_scale 1.5805e-02 / a_scale 7.6332e-02
- `dcdc_npu_qdq_8x4.onnx`：同样的图，输入补零到 [1, 8, 4, 4]（通道/空间对齐被 NPU 要求时用它），测试集 100.00%，对拍偏差 0.0e+00
- `dcdc_npu_weights.h`：C 数组（`--weights` 兜底模式用）
- `dcdc_npu_model.json`：输入顺序、类别名、隐藏层宽度、除数
- 标准化与除数已折进第一层；板上先做 u = [V/48, I/2.2, duty/95] 再喂模型
- 结构自检（`validate_onnx.py`）：三个模型都通过——拓扑序、Gemm 权重/输入维数、Conv 权重与通道、QDQ 的 scale/zp 类型都逐个查过

## 6. 怎么读这些数字（重要）

1. 数据是**物理仿真**的，且 4 个类别的边界（0.35/0.90 × 2 A）本身就写在生成器里，
   所以 test 准确率和「规则基线」几乎一样高。这只证明**链路通了、模型没写错**，
   不能当作真实工况识别能力的证据。
2. 只给 3 个瞬时量时，轻载/额定/近限流本质上是按电流大小分档；真实板子上还有纹波、
   采样相位、标定误差、温漂，边界样本会明显变多。
3. 真实数据到位后（`host.py` 的 CSV 或板内日志导出成同样列名），重跑 `train.py` 即可，
   建议同时把窗口统计量（std/斜率）加进特征，再对比一次。
4. 保护故障类在输入里只表现为「输出关断」（V≈0、I≈0、d=0）；OTP 没有可观测温度，
   与 OVP/OCP 停机后的签名相同，因此没有单列。

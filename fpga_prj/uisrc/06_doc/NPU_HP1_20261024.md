# Soft NPU: GP1 control and shared HP1 DDR interface

The active project is `E:/FPGA_2026/fpga_prj/fpga2026.al`.

## Interface

- `Video_NPU_0`: Anlogic Video_NPU 1.1 from the installed TD library.
- Soft NPU and all NN operators enabled. Image preprocessing and YOLO
  postprocessing are disabled; the PS application prepares power waveforms.
- Control: PS GP1 -> `NPU_Control_Matrix_0` -> AXI4-to-AXI-Lite converter ->
  NPU. Register window: `0x1f0000000..0x1f000ffff` (33-bit address, 64 KiB).
- DDR: NPU -> `NPU_HP1_Adapter_0` -> HP1 Matrix US1 -> read/write
  AXI4-to-AXI3 converter -> PS HP1. FDMA remains on Matrix US0.
- Matrix has two upstream ports and one downstream port, 64-bit data,
  33-bit addresses. FDMA priority is 1 and NPU priority is 0.
- Both NPU interfaces, the adapter, GP1 and HP1 use existing `clk_100m`
  and `Processor_System_Reset_0.peripheral_aresetn`. No new clock domain.
- `npu_soft_intr` -> existing IRQ Concat bit 15 -> PS F2P IRQ bit 15.
  The reference DTS uses GIC SPI 97, matching the official board example.
- Existing HDMI/HP0 timing, GP0 control, P481 payload, ADC, PI and PWM are
  preserved. Both HP ports ultimately share the PS DDR controller.

## ID and burst adaptation

The vendor NPU emits 6-bit IDs. The HP1 matrix needs one routing bit and
therefore accepts 5-bit IDs per upstream master to fit PS HP1's 6-bit ID.
`npu_hp1_axi_adapter.v` saves each original 6-bit ID, issues local ID zero,
then restores the original ID for B and all R responses. It permits one
outstanding read and one outstanding write independently. It does not
truncate IDs. Burst length (4 to 8 bits) and size (2 to 3 bits) are extended
without changing their values; native bursts are at most 16 beats.

This deliberately limits outstanding transactions; inference throughput
must be measured with the eventual model. AXI error responses and
backpressure propagate through the adapter.

## Model-facing contract

Input features, in order: output voltage, output current, actual duty.
Acquire them from the existing completed P481 DDR blocks. PS decodes the
signed 48-bit Q16 voltage/current and unsigned 32-bit Q16 duty, prepares a
temporal window, applies training normalization and model quantization,
then submits it to the runtime. Input and output tensors must not overlap
the live capture ring, weights, intermediate tensors or framebuffer.
Use the capture driver and NPU runtime's DMA/cache synchronization APIs
when changing ownership between DMA, CPU and NPU. Keep tensor buffers alive
until inference completes. A zero-copy reader must not release a capture
slot while the NPU still reads it; one capture owner distributes windows.

Classes: 0 = normal, 1 = load transient, 2 = oscillation. The classifier
should return three scores, with PS postprocessing selecting the class.
Window length, tensor layout, scale and zero point require the trained
model and are not hard-coded into the PL bus interface. One capture block
is 256 samples / 10.24 ms at 25 kHz; a model window may span several blocks.

This is still the DR1 Hard-NPU/Soft-NPU runtime architecture. Connecting
the soft NPU to HP1 does not relocate the hard NPU's internal DDR path.
The interface does not itself implement a trained classifier.

## Integration and validation

Rollback snapshot and reproducible generation scripts:
`tmp/npu_hp1_20261024`. Do not remove its `templates` directory without
repairing generated IP metadata that references these templates.

Static checks:

```powershell
python uisrc/05_tools/check_adc_fdma.py
python uisrc/05_tools/check_hdmi_display.py
python uisrc/05_tools/check_npu_hp1.py
```

`check_adc_fdma.py --write-address-map` restores the complete GP0/GP1/HP0/HP1
address manifest after DI generation. Preserve the composite dependency
`hdmi_clock_reset.v` and the normal project source entry for
`npu_hp1_axi_adapter.v` when generating DI.

The concurrent interface regression is `uisrc/02_sim/npu_hp1/run.do`.
It uses the production matrix, protocol converters, ID adapter, GP0/GP1
routing, FDMA and HDMI chain. NPU arithmetic and the PS/DDR are bus models.
The video output uses the previously verified mapped model of unchanged
production Stream-to-Video RTL to avoid its encrypted-RTL simulation issue.
The default interface regression programs a short 128x32 simulation raster;
production hardware remains 1024x600. Its checked pixels are not a new
full-resolution display or panel validation. A full-resolution testbench
source is also saved as `tb_npu_hp1_full1024.sv` for extended testing.
It is not a neural-network or physical-DDR validation.

Software handoff:
`uisrc/07_software/npu_probe/soft_npu_hp1.dtsi` and
`npu_condition_contract.h`. Merge the DTS fragment into the matching board
tree once; check the generated HPF DTS for duplicate NPU definitions.
Rebuild matching HPF/FSBL/BOOT/DTB/kernel and compatible NPU/CMA drivers and
Arm NN backend before board inference. Do not use the previous bit/HPF.
The newer Video_NPU 1.1 must also be checked against the deployed runtime.

Build/STA and simulation results are recorded in
`output/npu_hp1_20261024/README.md` after validation.

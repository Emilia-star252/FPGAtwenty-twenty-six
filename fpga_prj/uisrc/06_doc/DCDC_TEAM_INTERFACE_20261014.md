# FPGA2026：给 ARM 服务端 / 上位机队友的接口确认

日期：2026-10-15。按当前 `E:/FPGA_2026` 工程源码核对，顶层 `DCDC_top`，寄存器模块 `axi4lite_slave_v11.sv`。
本文对应已实现的 FPGA 接口；TCP 帧头、CRC、网络序号和 ACK/NACK 编码由服务端与上位机约定。

## 1. PS 地址空间中的 AXI 基地址

- **物理基地址：`0x80000000`**。
- 路径：PS `M_AXI_GP0` → AXI Protocol Converter → `axi4lite_slave_0.s_axi`。
- 地址 = 基地址 + **字节偏移**；统一使用 **4 字节对齐的 32 位读写**。
- 当前从机地址宽度为 8 位，寄存器范围为 `0x80000000～0x800000FF`。Address Editor 中的 `0x80000000～0x9FFFFFFF` 是分配的 GP0 地址窗口，不表示存在这么多独立寄存器；从机只解码低 8 位。
- FD 裸机按 BSP 的 MMIO 配置访问物理地址；Linux 服务端先映射该物理寄存器页，再使用映射得到的虚拟地址。映射一页 4 KiB 即可覆盖当前寄存器，访问限于下表定义的偏移。
- 当前 ARM 软件按小端访问；有符号数使用二进制补码。网络传输的字节序需在 TCP 协议中单独约定，不能直接假定与 MMIO 相同。

配套硬件识别值：

| 偏移 | 物理地址 | 内容 |
|---|---|---|
| `0x00` | `0x80000000` | `0x41444331`，ADC1 |
| `0x34` | `0x80000034` | `0x46495134`，FIQ4，四字采样帧 |
| `0x54` | `0x80000054` | `0x43545231`，CTR1，输出开关 / 电压给定接口 |

启动时核对识别值，确保下载的 bit 与本说明配套。
本次 64 V 更新沿用上述 ID，另外检查 `0x58` 读回 `0x00400000` 才是 64 V 上限；旧 48 V 版本读回 `0x00300000`。

## 2. 各量偏移、读写属性与格式

所有寄存器均为 32 位。RO=只读；RW=读写；W1C=向相应位写 1 清除该位。

### 队友需要的主字段

| 字段 | 字节偏移 | 物理地址 | 属性 | 格式与物理意义 |
|---|---|---|---|---|
| 实际电压 | `0x14` | `0x80000014` | RO | `int32`，有符号 Q16，除以 65536 得 V |
| 实际电流 | `0x18` | `0x80000018` | RO | `int32`，有符号 Q16，除以 65536 得 A |
| 温度 | **未实现** | — | — | 尚未接入，显示“未接入”或空值，不能上报为 0 ℃ |
| 实际 PWM 占空比 | `0x48` | `0x80000048` | RO | `uint32`，Q16 比例；乘 100 / 65536 得 % |
| 输出 / 控制状态 | `0x4C` | `0x8000004C` | RO | `uint32` 位图，具体位定义见下表 |
| 故障信息 | `0x4C` 的 bit3、bit7、bit8 | `0x8000004C` | RO | ADC 驱动故障、过流锁存、过压锁存；bit6 另作采样溢出诊断 |
| 输出开 / 关请求 | `0x40` | `0x80000040` | RW | bit0：1 请求开启，0 关断；复位为 0 |
| 目标电压 v_ref | `0x44` | `0x80000044` | RW | 非负 Q16，0～64 V；复位为 0 |
| 当前斜坡电压给定 | `0x50` | `0x80000050` | RO | `int32` Q16，除以 65536 得 V |
| 电压给定上限 | `0x58` | `0x80000058` | RO | Q16，当前 `4194304 = 0x00400000 = 64 V` |
| 非法命令标志 | `0x5C` | `0x8000005C` | RO/W1C | 非法命令标志；不清保护故障 |
| 清保护故障请求 | `0x60` | `0x80000060` | W1P | bit0 写 1；清给定并保持输出关；读回 0 |
| 清故障能力标识 | `0x64` | `0x80000064` | RO | `0x464C5431`（FLT1），旧 bit 不支持清除 |

**当前没有温度寄存器、电流给定寄存器和软件清 ADC 驱动故障命令。** 固定 2.5 A / 80 V 保护现已上传独立故障位，并支持经 0x60 清过流/过压。ADC bit3 仍需系统复位；可编程电流限值未实现。0x1C 保留，0x5C 只清命令错误。

`OUTPUT_STATUS`（`0x4C`）与 FIFO 状态字：

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | output_request | 软件请求开启输出 |
| 1 | output_active | **实际 PWM 输出已使能**；上位机“输出开”指示取此位 |
| 2 | adc_initialized | ADC 初始化完成 |
| 3 | adc_error | ADC 故障锁存，导致 PWM 关断 |
| 4 | pll_locked | PLL 锁定；1 为正常锁定状态 |
| 5 | pwm_armed | PWM 已在周期边界完成使能 |
| 6 | sample_overrun | 控制计算忙时又到达新样本，锁存诊断标志 |
| 7 | overcurrent_fault | 标定实际电流 >2.5 A，锁存至安全清故障或系统复位 |
| 8 | overvoltage_fault | 标定实际电压 >80 V，锁存至安全清故障或系统复位 |
| 31:9 | reserved | 当前为 0 |

保留原始 output_status 位图，故障字段可上传 output_status & 0x188（ADC / 过流 / 过压）；如果队友协议使用自定义故障码，请在服务端显式映射。保护立即拉低全部 PWM，并自动清零 OUTPUT_CTRL / VREF_CMD_Q16，原因位保持到清除成功。
保护按标定后的有符号实际值严格比较 >2.5 A / >80 V（不含等于，不取绝对值），不依赖上位机或 ARM 轮询。当前为 25 kHz 有效样本检测，首次越限样本被接收即关断，不等待 PWM 周期；从模拟越限到发现仍有采样和 ADC 转换/串行读取延迟。

### 采样与诊断寄存器

| 偏移 | 名称 | 属性 | 格式 / 说明 |
|---|---|---|---|
| `0x04` | ADC_STATUS | RO | 实时 ADC 状态位图，见下文 |
| `0x08` | SAMPLE_COUNT | RO | `uint32`，每次完整 ADC 样本加 1，溢出回绕 |
| `0x0C` | VOLTAGE_RAW | RO | V2 原始 16 位补码，符号扩展到 `int32` |
| `0x10` | CURRENT_RAW | RO | V3 原始 16 位补码，符号扩展到 `int32` |
| `0x80～0xFC` | scratch | RW | 32 个 32 位测试寄存器，无物理量意义 |

`ADC_STATUS`：bit0=初始化完成；bit1=驱动就绪；bit2=驱动忙；bit3=ADC 故障；bit4=PLL 锁定；bit5=控制采样溢出；bit6=已捕获完整样本；bit7=过流锁存；bit8=过压锁存；其余为 0。
注意 `0x04` 与 `0x4C` 的位定义不同。首次上报采样值可检查 `0x04.bit6`，避免把复位后的初始 0 当作一次有效测量。

### FIFO 寄存器（需要批量采样时使用）

| 偏移 | 名称 | 属性 | 说明 |
|---|---|---|---|
| `0x20` | FIFO_STATUS | RO | bit0=无可读字；bit1=采集使能；bit2=清空 / 复位中；bit3=发生过丢帧；bit4=当前队首字带 TLAST |
| `0x24` | FIFO_LEVEL | RO | `uint32`，FIFO 内 **32 位字数**，不是 ADC 帧数；不含源模块尚未送入 FIFO 的待发字 |
| `0x28` | FIFO_DATA | RO / 读出即弹出 | 每次有效读取弹出一个 32 位字 |
| `0x2C` | FIFO_CTRL | RW | bit0=采集使能；bit1=写 1 清空脉冲，读回为 0 |
| `0x30` | FIFO_DROP_COUNT | RO | `uint32`，丢弃的完整 ADC 帧数，饱和于 `0xFFFFFFFF`；清空时归零 |

FIFO_CTRL：写 0=停止接收新帧；写 1=采集；写 2=停止并清空；写 3=清空后继续采集。停止时已锁存的待发帧仍可送入 FIFO；清空会清掉 FIFO、待发帧、丢帧计数和包内序号，不清 ADC 或控制环。
清空后等待 `FIFO_STATUS.bit2=0`；读取 DATA 前检查 bit0=0。空 FIFO 或未对齐的 DATA 读取返回 SLVERR，不应用读取 DATA 的方式探测空状态。

上述表未定义的低地址为保留地址。旧的“向全部 64 个寄存器写测试图案”程序不适用于带控制功能的新版本；仅在 scratch 区做此类读写测试。

## 3. 数据格式与缩放

### 电压、电流

当前 ADC 驱动 `O_ad_range=1`，对应 **±10 V** 输入量程；原始码为 16 位有符号补码。
已确认 V2 电压通道分压还原 20 倍，V3 电流通道为 ADC 输入 1 V 对应 1 A，零电流输入为 0 V。

```text
ADC 输入电压 = raw × 10 / 32768
输出电压 V   = voltage_raw × 10 / 32768 × 20
输出电流 A   = current_raw × 10 / 32768

voltage_q16 = saturate_int32(voltage_raw × 400 + V_OFFSET_Q16)
current_q16 = saturate_int32(current_raw × 20  + I_OFFSET_Q16)

Vout = (int32_t)voltage_q16 / 65536.0
Iout = (int32_t)current_q16 / 65536.0
```

当前两个 OFFSET 均为 0。上述是按量程和确认比例完成的标称物理量换算，尚未用实测两点修正增益和零偏。Q16 数值已经包含 ADC 每码电压与前端比例，**不要再次乘 20 或除以 32768**。
有符号解释必须在除法前完成，否则负数会显示成很大的正值。

示例：电压 raw=7864 → `voltage_q16=3145600` → 47.998046875 V；电流 raw=3277 → `current_q16=65540` → 1.000061035 A。

### 占空比与给定

```text
Duty_percent = (uint32_t)duty_q16 × 100.0 / 65536.0
Vref_V       = (int32_t)vref_cmd_q16 / 65536.0
Vref_write   = round(Vref_V × 65536)
Output_on    = (output_status & 0x00000002) != 0
```

例如 duty=`32768 = 0x00008000` 为 50%，不是 32768% 或 0.5%。
占空比来自 PWM 已生效的高电平计数；关闭时应显示 0。`0x48` 是采样快照，关断后可能仍保留最后一帧；以实时 `0x4C.bit1` 判定实际开关状态，配套 C API 会在关断时将返回占空比置 0。

电压给定例：12 V=`786432 = 0x000C0000`；24 V=`1572864 = 0x00180000`；48 V=`3145728 = 0x00300000`；64 V=`4194304 = 0x00400000`。
允许范围为 0～64 V（含 64 V），与 ADC 测量量程是两个独立概念。GUI / 服务端应先读取 `0x58` 得到上限；配套 C API 已动态校验，毫伏接口的 64 V 参数为 `64000`。旧 48 V bit 的上限读回仍为 48 V，需下载本次更新的 bit。

### 输出控制顺序

1. 复位默认输出关、v_ref=0；ADC 继续运行。
2. 开输出：先写 `0x44` 设置非零目标，再写 `0x40=1`。
3. 开启命令被接受只代表请求已登记，实际是否开启读 `0x4C.bit1`。
4. 关输出：写 `0x40=0`，四路 PWM 关断；正的目标给定保留，重新开启从 0 斜坡启动。
5. 写 `0x44=0` 同时清除开启请求；零给定下请求开启会被拒绝。
6. 只写正的 v_ref 不自动开启。负数、超过上限或未对齐的控制写会返回 SLVERR，旧有效命令保持，并置位 `0x5C.bit0`。服务端应先校验命令范围。
7. 过流 / 过压会清零旧给定及开启请求并锁存原因。恢复正常采样后，先调用 DcdcAxi_ClearFaults 成功，再重新设置非零给定并开启；清除本身不会启动 PWM。最近样本仍越限、ADC 未就绪或同拍又越限时不清锁存；ADC 驱动故障仍需复位。

当前斜坡保持 48 V / 100 ms 的速率上下调整，0→12 V 约 25 ms、0→64 V 约 133.3 ms；`0x50` 可读取正在使用的斜坡给定。DCDC_top 的 V_REF_Q16 仅作为斜坡速率基准，命令上限由 AXI 的 VREF_MAX_Q16 定义。
当前电流环未启用，电压 PI 参数仍待整定。这里定义的是数字控制接口，不代表模拟功率级闭环已完成验证。

## 4. 更新方式：当前轮询，后续可接 DMA

**当前：ARM 轮询 AXI-Lite；未接中断，未实例化 / 启用 DMA。**

- ADC 完整样本节拍为 **25 kHz，约 40 μs / 帧**。电压、电流、占空比和 SAMPLE_COUNT 在同一有效采样沿锁存。
- 最新值寄存器会覆盖上一帧，适合低速 STATUS 显示。25 kHz 是硬件采样率，不等于上位机 TCP 上传率；服务端自行选择 STATUS 周期，例如 20～100 ms 属于显示周期建议。
- 为读取一致的 V/I/duty，先读 COUNT，再读 `0x14/0x18/0x48`，最后重读 COUNT；两次相同才接收，否则重试。配套 `DcdcAxi_ReadStatus()` 已实现此过程。
- `0x4C` 状态和 `0x44/0x50` 给定是实时字段，不属于上述三项的同帧快照；网络帧序号也不应与硬件 SAMPLE_COUNT 混为一谈。

需要保存逐帧数据时，使用现有 AXI-Stream FIFO。**FIQ4 每帧 16 字节，顺序固定：**

| 帧内字节偏移 | 类型 | 内容 |
|---|---|---|
| 0 | `int32` | 电压 Q16，单位 V |
| 4 | `int32` | 电流 Q16，单位 A |
| 8 | `uint32` | 实际占空比 Q16 比例 |
| 12 | `uint32` | OUTPUT_STATUS 同帧快照 |

四项在同一 ADC 有效采样沿捕获；无法接收新帧时丢弃完整新帧，DROP_COUNT 按帧累计。FIQ4 中没有温度、原始码、v_ref、时间戳或采样序号，不能按其他布局解包。
触发当帧的 FIFO 状态可能仍是故障前值，后续帧包含 bit7/8；及时显示原因应读实时 0x4C。FIQ4 字序和长度不变。
ARM 小端内存中的一帧可按 `<iiII` 解包；TCP 是否直接使用这种二进制布局需队友约定。

当前 FIFO 宽 32 位、深 4096 字，约容纳 1024 帧，对应约 40.96 ms 采样数据。当前每包 256 帧=1024 字=**4096 字节**；TLAST 在第 256 帧最后的状态字。
后续接 DMA 时保留这一采样格式，FIFO 出口接 S2MM 数据流，单包长度按 4096 字节匹配；届时由 DMA 消费数据，CPU 不再同时读 `0x28` 弹出同一 FIFO。

## 队友可直接复用的 C 接口

配套文件：`dcdc_axi.h`、`dcdc_axi.c`（项目中位于 `uisrc/07_software/dcdc_axi`）。

```c
DcdcAxi dev = {0};
/* 裸机传已按设备内存配置的 0x80000000；Linux 传 mmap 得到的虚拟地址。 */
int rc = DcdcAxi_Bind(&dev, mapped_register_base);

/* 以下分别放进对应命令处理分支，不要在启动时全部依次执行。 */
rc = DcdcAxi_SetVrefMilliVolt(&dev, 12000);  /* SET_VREF：12 V */
rc = DcdcAxi_SetOutput(&dev, 1);            /* OUTPUT_ON */
rc = DcdcAxi_SetOutput(&dev, 0);            /* OUTPUT_OFF */
rc = DcdcAxi_ClearFaults(&dev);             /* 现有清故障命令 */

DcdcStatus s;
rc = DcdcAxi_ReadStatus(&dev, &s);          /* 周期构造 STATUS */
```

调用方串行执行状态读取与命令写入。Bind 只检查硬件标识，不开启输出。
C API 返回值：0=成功；-1=参数错误；-2=超范围或零给定开启；-3=硬件标识 / 回读不符；-4=快照重试失败；-5=故障未解除或禁止开启。ClearFaults 会先核对 0x64 的 FLT1，再关闭输出、清给定、写 0x60 并检查实际故障回读；只有返回 0 才可回复清除成功。
这些是软件调用结果，不是 FPGA 故障码。OUTPUT_ON 成功可回复“请求接受”，之后 STATUS 的 output_active 再报告实际状态。

本交接只提供寄存器说明与访问 API；目前 FD 工程为 standalone 裸机，Linux 服务端的设备映射、TCP 协议处理与线程调度由队友实现。

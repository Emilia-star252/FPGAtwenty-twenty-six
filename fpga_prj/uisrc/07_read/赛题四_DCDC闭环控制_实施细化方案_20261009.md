## 2. 项目目标与职责

核心目标：用 FPGA 对现有四开关功率板实现可调稳压、输出限流、同步采集和故障关断；Linux 提供操作、存储与通信；NPU 完成板端工况识别。

```text
24 V 电源 → 四开关功率板 → 12～60 V / 最大 2 A 负载
                    ↑                 │
                 门极驱动              ├─ Vout 采样 ─┐
                    ↑                 └─ Iout 采样 ─┼→ DAQ001 → PL
          调制 / 使能 / 故障关断           Vin 建议采样 ─┘          │
                    ↑                                            │
            功率板独立快速保护                          标定、稳压、限流、状态机
                                                                 │
                                              AXI 双向寄存器 / FIFO
                                                                 │
                                       PS Linux → 界面 / CSV / NPU
                                                                 │
                                              RS485 Modbus 通信
```

- PL：同步采集、控制运算、调制、运行状态与故障锁存。
- 功率板保护：危险开关电流的独立快速检测及驱动禁止。
- PS：受限的设定值与启停请求、数据读取、本地存储、界面服务及 NPU 调度。
- NPU：告警与记录，不参与 PWM 更新及快速保护。

实时控制不经过 Linux。上位机断开后闭环继续运行；Linux 心跳丢失时按冻结的许可策略停机。两者是不同事件。

## 4. 功率板参数与接口冻结

### 4.1 接入前必须整理的信息

| 参数 / 接口 | 应提供的内容 | 决定的设计 |
|---|---|---|
| 电感 | L、饱和电流、额定温升电流、直流电阻 | 电流纹波、峰值与模型 |
| 电容 | 输入/输出电容值、耐压、ESR | 纹波、动态、过压裕量 |
| MOSFET | 型号、耐压、导通电阻、栅极电荷 | 器件应力、损耗及驱动 |
| 驱动器 | 型号、供电、输入电平、EN 极性、高侧供电方式 | 门极接线、持续导通、停机行为 |
| 20 ns 死区 | FPGA、驱动器或其他电路中的产生位置 | 明确唯一责任边界及实际时序 |
| 电压采样 | 分压比、缓冲、RC、输出范围 | 标定与相位延迟 |
| 电流采样 | 位置、分流/传感器、增益、偏置、带宽 | Iout 换算、限流响应 |
| 快速保护 | 检测量、比较器、阈值、关断路径、锁存方式 | 是否能独立保护功率级 |
| 接线 | 四路命令、EN、FAULT、地及 IO 电平 | 顶层端口、管脚约束 |

20 ns 先保留为现有设计参数。其是否足够，要结合驱动传播差、MOSFET 关断和实测 Vgs 判断；不能仅凭 RTL 互补关系认定不存在直通，也不应无依据重复插入另一段死区。

### 4.2 电流与频率核算

在 60 V / 2 A 工作点，理想输入平均电流为 5 A。按效率 90% 举例，输入平均电流约 5.56 A；该效率仅作预算假设。

升压 CCM 条件下，理想低侧占空比和电感纹波为：

```text
Dboost ≈ 1 − Vin/Vout
ΔIL ≈ Vin × Dboost / (L × fsw)
IL,peak ≈ IL,avg + ΔIL/2
```

以 24→60 V、25 kHz、假设 L=100 µH 举例，Dboost≈0.6，ΔIL≈5.76 A。此例说明电感和限流必须重新核算，不代表现有板卡电感为 100 µH，也不代表该值应直接采用。

应校核 12～60 V 全范围内的器件电压、峰值电流和温升。若现有磁件不支持 25 kHz，先调整功率边界或磁件设计，再做额定功率验证。

## 5. 四开关调制实现

### 5.1 定义与基础模式

定义 A 为输入侧半桥、B 为输出侧半桥，电感连接在两个半桥中点。AH/AL、BH/BL 分别表示两侧上管/下管的有效导通命令，具体 FPGA 引脚必须按原理图映射。

| 模式 | A 半桥 | B 半桥 | 理想关系 |
|---|---|---|---|
| Buck | AH/AL 开关 | BH 导通、BL 关闭 | DAH≈Vout/Vin |
| Boost | AH 导通、AL 关闭 | BH/BL 开关 | DBL≈1−Vin/Vout |
| 过渡区 | 专门设计连续调制 | 配合连续调制 | 不能用上述极限公式生硬切换 |

理想示例：24→12 V 的 DAH≈50%；24→48 V 的 DBL≈50%；24→60 V 的 DBL≈60%。这些值用于开环核对及前馈初值，不是最终闭环实测占空比。

分区模式需要核对高侧持续导通能力。若现有驱动仅靠普通自举且不能维持高侧供电，必须解决驱动供电或调整调制方式，不能直接执行上管常开策略。

### 5.2 RTL 分工

建议增加 `buck_boost_modulator`，接收控制请求、运行许可和故障，输出四路门极逻辑命令及实际生效占空比。其职责包括：

1. 依据冻结的控制变量生成两侧独立调制请求。
2. 限制可实现的占空比、最小脉宽及模式边界。
3. 与已有死区环节协调，同一半桥不得重叠导通。
4. 正常请求在 PWM 周期边界原子生效；故障关断不等待周期边界。
5. 输出实际模式和实际生效请求，供抗饱和、日志及 AXI 使用。

过渡区需单独完成：模式判据、滞回、两侧占空比连续映射、积分状态衔接及驱动刷新约束。当前条件不足以冻结过渡区宽度和具体波形。

实施顺序：固定升压模式小电流验证 36/48 V → 验证 60 V → 固定降压模式验证 12/18 V → 在模型与实物中验证跨越 24 V 的调节。

## 6. 闭环与输出限流

### 6.1 基础架构

采用“电压闭环 + 输出电流限流”。现有 Iout 反馈不能直接套用电感电流 IL 内环模型。若保留级联双环结构，必须针对实际输出电流对象重新建立模型与整定，不能沿用电感电流环参数。

基础运行目标：正常负载下稳压；达到允许输出电流时限制功率请求；不可恢复或危险异常进入 FAULT。

可选增强为 CV/CC 控制：电压与输出电流调节器分别产生同一物理含义的调制请求，经协调选择后输出。两个调节器都应感知最终实际请求，避免非主导调节器积分累积。不能把不同模式或不同单位的输出直接比较取最小。

例如给定 60 V、负载 24 Ω，恒压需要 2.5 A；若采用 2 A 恒流控制，输出应降到约 48 V。正常恒流不应直接标记为故障。

### 6.2 模型与整定流程

1. 根据实际功率板建立 PLECS 开关模型，包含器件与磁件主要非理想参数。
2. 加入采样前端、DAQ001 滤波/转换、串行读取、数字计算及 PWM 保持延迟。
3. 选择代表工作点：12、18、36、48、60 V，以及过渡区两侧；覆盖轻载和允许大负载。
4. 开环核对反馈极性、占空比关系、电流纹波和器件应力。
5. 先整定稳压，再整定限流/恒流，并验证两者切换。
6. 将离散控制转换为定点，明确量纲、位宽、舍入、限幅和溢出策略。
7. 浮点、定点与 RTL 使用同一输入序列对照，随后做实际参数配置下的综合及 STA。
8. 小电流实物整定，再扩大负载范围。

升压区的右半平面零点限制环路带宽。不能根据 ADC 采样率或 PI 计算速度直接确定控制带宽，也不能预先保证全范围共用一组 PI 增益。

### 6.3 PI 实现要求

- 固定现有算法约定或明确迁移到标准离散 PI；现有代码积分增量是 `Kp×error×Ki`。
- 抗饱和允许积分向退出饱和的方向变化，或采用回算。
- 将调制限幅、限流接管和输出禁止纳入抗饱和跟踪。
- 积分状态限制与实际输出单位和范围一致。
- 停机、故障、重启与模式切换的积分处理有明确规则。
- 软启动斜率和预充电输出的启动行为在模型中验证后冻结。

## 7. 同步采样、标定与时序

### 7.1 通道配置

优先保持现有 Vout、Iout 通道映射，另建议接入 Vin。DAQ001 的实际实装芯片、输入量程、串行模式、IO 电压和已焊接口数量均按实物核对。

电压分压须覆盖 60 V 正常输出及规定的过冲裕量。电流传感器量程不能在 2 A 附近立即饱和，否则无法可靠观察限流过冲。ADC ±5 V 模拟量程与 FPGA IO 电压是不同概念。

标定使用：

```text
Vout = kv × raw_v + bv
Iout = ki × raw_i + bi
Vin  = kin × raw_in + bin
```

保存原码、仪器读数、拟合系数、残差、单位和标定版本。零点及至少两个非零点用于初步拟合，另取独立检查点验证；电流必须处理实际零偏及正负方向。

### 7.2 调度建议

控制节拍独立于门极输出使能运行，READY 和 FAULT 阶段仍允许诊断采样。采样先采用固定、可配置相位，依据实际开关边沿选择安静窗口。若采用随占空比变化的相位，应显式处理采样间隔变化及采样电流代表性。

当前 6.25 MHz、双 DOUT、每路 64 位读取，串行帧时间约 10.24 µs。已有行为仿真测得 CONVST 到占空比请求就绪约 14.4 µs，数字链路可在 40 µs 周期内安排，但需实板确认。

AD7606 的 ±5 V 档模拟滤波典型群延迟为 15 µs。这是环路模型的一部分，不应简单等同于额外的固定数字等待时间。若实装芯片为其他型号，必须使用其对应参数。

实测需区分：采样请求、实际 CONVST、完整数据有效、控制结果提交和 PWM 实际生效。记录最大值及是否错过预定更新边界。

ADC 外部 STA 已按工程预算建立，但预算尚需与实物核对。更改系统时钟、SPI 半周期、芯片、供电或接口后重新推导，不保留失配的多周期约束。

## 8. 保护与状态机

### 8.1 两层保护

| 层级 | 检测与动作 | 验证方式 |
|---|---|---|
| 独立硬件 | 检测危险开关/电感电流，直接禁止驱动 | 不依赖 ADC、Linux 或正常 FPGA 节拍测试关断 |
| PL | ADC 错误、样本超时、输出过压、持续过载、运行许可丢失等 | 故障注入、故障锁存及人工恢复 |

输出电流采样不能替代快速开关电流保护。启动给输出电容充电时，负载输出电流与电感电流也不相同。现有功率板若已有该保护，复用并验证；否则补齐独立检测与关断路径。

门极全部关闭不等于输出立即归零，需核对续流、储能及可能的反灌路径。保护阈值和最大关断延迟根据器件应力、纹波及测量误差计算后冻结；不机械沿用旧 Buck 目标。

### 8.2 状态定义

| 状态 | 门极与控制行为 | 转移条件 |
|---|---|---|
| INIT | 驱动禁止，初始化 ADC 和控制状态 | 初始化结束进入 READY |
| READY | 门极关闭、持续采样、检查反馈与许可 | 明确启动请求且所有条件满足 |
| SOFT_START | 斜坡给定、限流有效、受控输出 | 达到运行条件进入 RUN |
| RUN | 正常稳压或正常限流 | 停止返回 READY；异常进入 FAULT |
| FAULT | 禁止驱动、锁存原因、保留诊断 | 原因解除且人工复位后返回 READY |

软件不能直接清除尚存在的硬件故障。启动至少要求有效反馈、允许设定、无故障及驱动就绪。采样错误与样本年龄均须检测，防止保留旧占空比持续输出。

## 9. AXI、Linux 与日志：独立新建

完整实现方法、寄存器分区草案及验证门见 [独立重规划方案](E:/FPGA_2026/uisrc/07_read/AXI_Linux_NPU_独立重规划方案_20261009.md)。本节概括当前实施路线。

### 9.1 AXI 实施顺序

1. 根据官方 Linux 驱动开发篇 AXI-GPIO 实验，验证本平台 PS→PL 通路、时钟、复位及 Linux 访问。
2. 自建 AXI-Lite 从设备，首先只实现 ID、ABI、SCRATCH 与计数器，仿真握手后再做实板读写。
3. 定义新协议，加入配置影子寄存器、原子提交/确认、独立停止请求和一致测量快照。
4. 增加滤波抽取后的 1 kSPS 遥测 FIFO、丢帧统计，再按实测需要增加中断。

物理基地址、AXI 域频率、实际端口名及中断号由新工程导出并冻结，不继承任何失败工程设置。AW/W 必须独立接收，响应背压不得丢失数据或重复消费 FIFO。

多位配置使用一包一确认邮箱；测量使用整包快照或异步 FIFO。域复位后重建会话，禁止采用陈旧启动请求。停止与故障优先于普通配置更新。

### 9.2 Linux 实施顺序

1. 使用官方匹配软件包建立可重建启动基线，记录工具及镜像版本。
2. 新硬件导出 HPF/bit，FD 生成匹配 FSBL，同步设备树与内核/rootfs，形成完整启动版本。
3. 新建薄 platform 驱动及最小测试工具，从实际设备树资源访问 MMIO。
4. 新建唯一配置写入者 `dcdc-service`，处理命令、采样、许可心跳与数据分发。
5. 先 CLI 后 PC 界面；日志与 NPU 使用独立有界队列/进程。

服务启动、重启均不自动启动电源。界面断线不影响板上服务许可；关键设备访问或调度失效时停止心跳，由 PL 按策略停机。心跳拟每 100 ms 更新、500 ms 超时，需压力测试后冻结。

### 9.3 数据与存储

- 界面/状态约 10 Hz；连续遥测建议 1 kSPS；控制周期动态测试另保存 25 kSPS 短时数据。
- 新帧草案为 40 字节，1 kSPS 原始流约 40 kB/s、3.46 GB/天；日志必须轮转与限制总量。
- CSV 用于低速状态/导出，连续数据可用带版本头的二进制格式。
- FIFO 满时丢遥测并计数，不阻塞控制。NPU 从内存窗口读取，不回读 CSV 等待磁盘。
- 保存 HPF/bit/FSBL/DTB/kernel/rootfs、ABI、标定、模型和特征版本的 manifest，确保板上实际构建可追溯。

## 10. RS485 与 NPU

### 10.1 RS485

采用底板接口，先实现 Modbus RTU 从站 03 读寄存器、06 写单寄存器。冻结从站地址、波特率、数据格式、寄存器单位及异常响应。

远程写入与本地设置共用边界检查及命令仲裁。读取返回一致快照；停止命令优先于启动；不能通过总线绕过保护。验证 CRC、帧间隔、DE 方向、超时及连续运行，保存总帧数和错误统计。

### 10.2 NPU：按官方实际软件路线新建

本次核对官方 NPU 演示包：应用使用 Arm NN ONNX Parser、Optimize、LoadNetwork 与 EnqueueWorkload；默认后端为 `Alnpu,CpuAcc,CpuRef`，允许 CPU 回退。官方工程包含 NPU 软核及相应设备树，不能只使能 Linux 配置后假定模型已在 NPU 执行。

实施路线：完整官方示例 → 文件/内存输入的无摄像头 `npu-probe` → 严格 `Alnpu` 后端的自定义候选模型 → 正式数据训练 → 独立在线 `npu-worker`。精简视频外围时保留实际 NPU 所需的硬核/软核、DDR/CMA、时钟、复位和中断依赖。

先验证算子、形状、量化格式及导出工具，再确定 8～16 维特征小网络等候选结构。官方已有 UINT8 量化 ONNX 可作基线；自定义模型最终 INT8/UINT8 按真实后端支持及赛题核对。不能虚构专用模型转换命令或预先保证任意模型可部署。

正式数据从 1 kSPS 流构造 100 ms 窗口，提取 Vout/Iout 波动与变化特征。正常稳态、软启动、负载阶跃和正常限流须与异常区分，按独立试验轮次划分数据。Vin 未安装时不伪造该输入，故障位不作为唯一特征。

验收保存后端分配或等效 profiling、对应硬件/驱动执行证据、量化参考对照、混淆矩阵及耗时。低 CPU 占用和运行成功都不能单独证明 NPU 执行。NPU 失效显示不可用，不影响快速保护与故障锁存。

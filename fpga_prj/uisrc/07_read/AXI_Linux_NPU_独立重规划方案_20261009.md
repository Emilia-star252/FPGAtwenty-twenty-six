## 1. 当前起点和重新规划的结论

2026-10-09 核对当前 `fpga2026.al`：源清单包括 ADC 驱动、PI、PWM、DCDC_top、PLL 与 ChipWatcher，没有 PS 系统 IP 或 AXI 从设备。当前顶层没有 PS 接口，控制使能仍为常量。AXI、Linux 应用和 NPU 集成均按新功能建立。

采用三条可分别验收的路线：

1. AXI：官方 PS→PL 通路验证 → 自建最小寄存器从设备 → 跨域配置/快照 → 采样 FIFO。
2. Linux：官方匹配启动环境 → 新硬件对应 FSBL/设备树 → 最小设备访问 → 控制服务、日志和界面。
3. NPU：官方 NPU 示例 → 无摄像头的模型推理程序 → 自定义量化模型 → 电源数据集与在线识别。

在调试 AXI 和 Linux 时禁止功率输出。NPU 可行性验证在早期开展，不等待功率闭环全部完成。

## 3. 新系统架构

```text
PL 控制域，100 MHz，25 kHz 更新
  ADC → 标定 → 稳压/限流 → 四开关调制 → 门极命令
                  ↑                 │
            配置邮箱/确认          独立保护和故障锁存
                  │                 │
             跨时钟域边界            │
                  │                 ↓
PS→PL AXI 主通路 → AXI-Lite 自定义控制外设
                  ├─ 身份/版本/测试寄存器
                  ├─ 配置影子寄存器与提交/确认
                  ├─ 一致测量快照
                  └─ 采样 FIFO / 中断 / 丢帧统计
                              │
                      Linux 薄平台驱动
                              │
                  dcdc-service，唯一配置写入者
                    ├─ 操作界面 / 命令仲裁
                    ├─ logger：分批记录
                    └─ npu-worker：只读窗口、上报告警

板载 NPU 运行链：量化 ONNX → Arm NN ONNX Parser → Alnpu 后端
                    → 官方要求的硬核/软核、驱动、DDR/CMA 和中断
```

AXI 域时钟拟从 PS 导出，实际频率由新建 PS 设计决定，不预先宣称为 50 MHz。与控制域不同时，使用明确的 CDC 结构。NPU 所需互联依据官方工程重新建立，不能把小型 AXI-Lite 控制接口当作完整 NPU 数据通路。

## 4. AXI 从零实施

### 4.1 A0：先验证官方通路

在本项目工作区内建立独立验证目录，依据官方 AXI-GPIO 资料生成适配当前器件与工具版本的 PS/PL 设计。此阶段功率级禁止输出，首先验证 PS 时钟、复位、PS→PL 主通路及 Linux 可见的外设。

先保存生成文件中的端口名、地址宽度、协议、时钟、复位、地址窗口和中断信息；需要协议或位宽转换时使用当前工具支持的转换 IP。不凭空指定 GP 端口名或物理基地址。

退出条件：对应镜像启动，Linux 可以读取或控制一个已知的 PL 外设；保存硬件导出物、启动日志与访问记录。

### 4.2 A1：自建最小 AXI-Lite 从设备

首版只加入 4 个寄存器：ID、协议版本、SCRATCH、AXI 域计数器。ID 和协议由本项目新定义，不能与其他布局共用无法区分的标识。

RTL 必须满足：

- AW 与 W 分别接收，不要求同时到达。
- 按 WSTRB 处理写入，写响应前完成本地接收。
- B/R 被阻塞时保持 VALID 与响应内容。
- 读请求返回本地寄存器，不能等待 ADC 或 Linux 完成某项工作。
- 非对齐、未定义地址、非法读写权限有明确响应。
- 复位可以中止内部未完成事务，恢复后不保留过期启动请求。
- 第一版只支持有限在途事务，背压行为明确。

在仿真中覆盖 AW/W 先后次序、背压、字节写、错误地址和复位；上板只访问已导出的有效窗口。系统对未配置 PL 或无响应总线访问的防护，需要核对 PS/互联超时能力，不能认为用户态超时能解除硬件总线挂起。

`BOOT_SESSION` 不能只是每次复位都相同的常量。应采用可区分会话的握手策略，例如 PS 启动随机 nonce 与 PL 回显结合；无可靠持久计数器时，不宣称具备掉电单调计数能力。

### 4.4 A2：配置和测量跨域

配置采用一包一确认邮箱：PS 写影子寄存器 → COMMIT 锁存载荷 → 载荷保持稳定 → 请求经过同步器 → 控制域完整接收、检查边界 → 在控制周期边界采用 → 返回 ACK 和结果。ACK 前不得修改在途载荷；新提交返回忙或明确拒绝。

快照采用请求/确认：控制域复制同一帧对应的测量与状态 → 保持整包稳定 → AXI 域捕获整包 → 发布 ACK → 软件读取冻结快照。尚无有效采样时返回有效位为 0 的快照，不无限等待第一帧。

多位数据不能逐位两级同步。独立域复位后应重新建立握手会话，清除未处理启动请求，禁止把复位产生的 toggle 差解释成新命令。停止和故障事件独立于普通配置邮箱，具有更高优先级。

### 4.5 A3：采样 FIFO 与带宽

建议首版将 25 kSPS 控制采样经滤波后抽取到 1 kSPS，使用异步 FIFO 传给 PS，不先引入 DMA。

固定帧草案为 40 字节、10 个 32 位字：采样序号、时间戳低/高字、Vout、Iout、Vin、A/B 实际占空比计数、状态/模式/有效位/故障摘要、实际配置序号。Vin 未安装时保留字段并清除其有效位。完整故障细节由快照读取。

候选深度 512 帧，约 20 KiB，能缓存约 512 ms 的 1 kSPS 数据。该值需核对器件 BRAM 预算与服务实测延迟后冻结。Linux 拟每 20 ms 批量读取，单批上限例如 64 帧，积压时按水位继续排空。

FIFO 满时丢弃新遥测帧并计数，不阻塞控制。单个读响应只消费一个字，RREADY 背压不得重复消费；驱动必须保持帧边界，发生清空/重置时报告新的流会话。1 kSPS、40 字节原始流约 40 kB/s，即约 3.46 GB/天，CSV 更大，因此必须轮转与限额。

若实测 AXI-Lite 批量读取不足，再设计 DMA、缓存一致性与驱动；不能仅因存在 DMA IP 就提前增加集成依赖。

## 5. Linux 从零实施

### 5.1 L0：建立可复现的启动环境

记录板卡版本、启动介质、实际 TD/FD 版本、IP 版本、官方软件包版本、交叉编译器、内核、rootfs、DTB 和启动日志。先使用官方匹配基础系统验证 PS UART、存储及必要网络。

针对新硬件按官方流程执行：TD 综合/实现 → 导出包含 bit 的 HPF → FD 生成平台与 FSBL → 同步新设备树 → 构建 U-Boot/内核/rootfs → 生成匹配启动镜像。具体脚本参数按所用版本核对，不能混用不同设计的 bit、FSBL 和 DTB。

验证阶段准备单独测试启动介质。本文只规划流程，不执行介质格式化、烧写或替换现有启动环境。主板按其硬件手册供电，功率板的 24 V 输入不能直接当作主板供电。

### 5.2 L1：设备树和最小访问

为新的控制外设建立专用设备树节点，`reg` 来自实际硬件地址导出，`interrupts` 来自实际 PL→PS 映射，地址单元数量与上级总线一致。中断尚未连接时先轮询，不填入示例中断号冒充实际连接。

最终建议使用薄 platform 驱动：从设备树获取资源，使用匹配内核支持的资源映射 API 和 `readl/writel`，提供固定结构的配置、快照与批量帧接口。核对 ARM MMIO 访问顺序，不能仅依赖普通指针或 `volatile`。

为缩短首次寄存器验证，允许独立 smoke 工具在已确认有效的窗口内通过受控 MMIO 读取 ID/SCRATCH；正式服务不直接映射任意物理内存。若采用 UIO 做中间验证，先核对目标内核的 UIO 配置及实际绑定机制，不能假定写一个设备树节点即可出现 `/dev/uio0`。

驱动职责：识别协议、序列化配置、复制快照、批量排空 FIFO、管理中断/轮询、返回明确错误。多个应用不得竞争读取流端口或写配置；通过单一服务分发数据。

### 5.3 L2：控制服务

新建 `dcdc-service`，不复用失败工程的软件。模块建议为：

| 模块 | 职责 |
|---|---|
| `device_access` | 封装新驱动接口与协议校验 |
| `command_manager` | 唯一配置写入者，仲裁本地/RS485/界面请求 |
| `sample_receiver` | 批量取帧、检查序号和时间戳、维护缓存 |
| `health_monitor` | 在服务关键路径健康时刷新心跳 |
| `logger` | 异步写盘、轮转、磁盘不足处理 |
| `ui_gateway` | 给 CLI/PC 界面提供状态与命令入口 |

启动流程：验证 ID/ABI/能力 → 获取快照确认停止 → 建立新会话 → 下发初始受限配置 → 等待 ACK → 开放界面。服务启动不自动启动电源，进程重启不恢复上次运行许可。

建议心跳初始设计值为每 100 ms 更新，运行超时 500 ms，均需结合系统压力测试冻结。心跳不是一个独立线程无条件自增：设备读写或关键调度失效时停止续期，使 PL 撤销运行许可。日志/NPU 独立失败则报告降级，不默认拖垮硬件保护。

### 5.4 L3：界面、日志与异常行为

第一版先做 CLI，再实现 PC 图形界面，通过以太网应用协议连接板上服务；网络不可用时再使用独立数据 UART/USB 串口。调试控制台 UART 保持用于启动和维护，不与二进制上位机协议争用。

界面约 10 Hz 刷新，显示 Vout/Iout、给定、状态、CV/CC、故障、实际调制与 AI 状态。断开界面不撤销板上服务许可。

本地遥测存储采用有界队列，按时间或容量轮转，保留总量上限。CSV 用于低速状态与导出；连续 1 kSPS 原始数据优先采用有版本头的二进制格式。NPU 窗口直接来自内存采样流，不能等待 CSV 写盘再回读。

采样断帧、FIFO 溢出、磁盘满、界面断线、NPU 失败分别记录。NPU 掉线显示不可用及结果年龄，不能继续显示旧结果为当前正常。关键控制访问失败则停止许可并报告。

### 5.5 系统版本清单

每套可下载构建保留 manifest：工程和源码版本、HPF/bit/FSBL/DTB/kernel/rootfs 哈希、ABI、采样帧格式、标定、模型、特征提取版本、库版本和构建命令。明确板上实际加载版本，不能用另一构建的时序报告作为当前版本证明。

## 6. NPU 基于官方路线重新实施

### 6.1 N0：完整官方示例基线

使用官方 NPU `demo.zip` 对应工程和软件，验证其要求的 NPU 硬核/软核、DDR/CMA、中断、驱动、动态库和量化模型。首次复现可以使用示例要求的摄像头/显示；其作用是建立工具链基线，不是本项目电源 AI 交付。

保存默认后端运行结果后，另用仅 `Alnpu` 的后端选择进行核验。官方应用支持 `--backends` 选项，但是否所有示例算子都能在该设置下运行必须实测；失败时记录不支持的算子或依赖，不能改回 CPU 回退后宣称 NPU 通过。

本次已确认的官方软件路线为：

```text
量化 ONNX 文件
 → IOnnxParser::CreateNetworkFromBinaryFile
 → armnn::Optimize，指定后端
 → LoadNetwork
 → 量化输入缓冲区
 → EnqueueWorkload
 → 输出张量与后处理
```

该路线未证明必须先生成某种专用离线模型文件；自定义量化/导出工具与后端内部编译需求应再核对实际 SDK。不要凭通用 NPU 经验虚构转换命令。

### 6.2 N1：无摄像头的最小推理程序

新建 `npu-probe`：加载官方已支持模型，读取文件/内存中的固定测试输入，执行推理并输出结果、张量类型、形状、量化 scale/zero point、所用后端和耗时。

从官方代码借鉴的是 ONNX Parser、运行时、缓冲分配和执行方式；去掉摄像头、视频解码、YOLO 后处理与显示依赖。官方示例的图像预处理不能直接用于电气特征。

逐步精简 PL 外围：每次只去掉一个已确认非 NPU 必需的模块，并重新验证。不能因为无需视频就删掉 `NPU_SOFT` 或其 AXI/DDR/时钟/复位/中断依赖。是否某个特定模型只需硬核，要由实际后端图和平台依赖证明。

所有 Parse/Optimize/Load/Enqueue 的返回值、空指针及错误消息必须检查。区分一次性加载时间、单次硬件推理时间与预处理至结果的端到端时间。

### 6.3 N2：先做算子与模型可行性试验

首选候选是低维特征分类器，例如 8～16 个特征、一个小隐层、二分类输出。具体层型、输入形状、ONNX opset 和量化表示不在训练前武断冻结。

实施方法：

1. 获取实际后端支持信息；用单层小模型验证全连接或卷积、激活和所需输出算子。
2. 核对官方 UINT8 模型的量化表示，确定可复现的量化导出工具；再按支持范围选择 INT8/UINT8。
3. 对候选模型运行严格后端测试，保存优化图/层分配或等效 profiling。
4. 与主机同量化输入的参考结果比较，核对张量布局、scale、zero point、饱和范围及允许误差。
5. 只有候选可在真实板端执行后，再开展正式模型训练。

若全连接路线不支持，改用已验证的小卷积结构承载特征向量/时间窗口，而不是直接回退 CPU。最终结构选择以实测结果记录。

### 6.4 N3：电源工况数据与训练

第一版只承诺根据 Vout/Iout 识别正常与异常波动，不承诺仅凭两路信号准确定位所有器件故障。正常类别包括稳态、规定负载阶跃、软启动和正常限流；异常类别由独立试验条件定义。

建议从连续 1 kSPS 流构造 100 ms 窗口，即每窗 100 点。特征候选包括：相对电压误差的均值/极值/标准差、Iout 均值/极值/标准差、变化率、振荡幅度等。Vref/Ilimit/模式用于解释工况；Vin 仅在真实通道存在时使用。

归一化、窗口长度、缺样处理和量化参数存入模型配套 manifest。训练与运行使用同一特征代码或逐向量对照验证。缺样窗口标记无效，不补零冒充正常样本。

按独立试验轮次划分训练/验证/测试，避免相邻窗口泄漏。故障位可辅助标注，不能作为唯一输入把分类变成已有阈值的重复判断。训练数据采用受控工况，不为制造标签施加超过功率板能力的条件。

### 6.5 N4：在线集成与执行证据

`npu-worker` 使用独立进程，只读服务提供的特征窗口，上报窗口序号、类别、置信度、模型版本、推理耗时和有效状态。它没有电源配置写权限，不向控制路径发送“解除保护”。

默认每 100 ms 推理一次作为设计起点；先测延迟与系统负载，再冻结节拍。过期窗口丢弃并计数，不能无限排队使结果脱离当前工况。

证明 NPU 参与执行至少需要：仅 `Alnpu` 的执行设置、已学习算子的后端分配或等效运行时证据，以及与该次推理对应的硬件/驱动完成记录。CPU 占用低或运行速度快都不是充分证据。CPU 做特征提取和后处理允许，但要分开报告。

若运行时无法直接导出层分配，实施时补充可支持的 profiling/驱动证据，并记录覆盖范围；证据不足时不写“全模型 NPU 已验证”。

| NPU 执行 | 严格后端、自定义输入、参考对照 | 执行位置与结果均有证据，不依赖 CPU 推理回退 |
| AI 数据 | 按轮次独立测试、正常限流与阶跃 | 报告混淆矩阵及各工况错误，不只报总体准确率 |
| 综合压力 | 初步目标连续 60 min：采样、日志、界面、NPU、通信同时运行 | 无失控/总线死锁，所有缺口和降级均可解释 |

连续时间、允许丢帧率、推理延迟和准确率目标在基线测量后冻结。未通过门限的结果保持“未通过”，不以功能截图代替量化验证。
